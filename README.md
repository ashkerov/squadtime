# SquadTime — планировщик встреч (локальная версия)

Сайт, который помогает компании друзей найти время для встречи. Каждый отмечает на сетке,
когда может, — сайт показывает тепловую карту и три лучших варианта, фиксирует время и место
и выдаёт файл `.ics` с напоминаниями.

Локальная версия работает **целиком в браузере**: без сервера, базы данных и денег. Все данные
лежат в `localStorage` под ключом `kogda:v1`. Полное ТЗ — в файле
[«ТЗ Планировщик встреч — локальная версия сайта.md»](./ТЗ%20Планировщик%20встреч%20—%20локальная%20версия%20сайта.md).

## Запуск

Нужен Node.js 20+.

```bash
npm install
npm run dev            # разработка: http://localhost:5173
npm run dev -- --host  # открыть с телефона в той же Wi-Fi сети
npm run build && npm run preview  # проверить сборку
npm test               # тесты (Vitest)
npm run lint           # ESLint
npm run format         # Prettier
```

Оговорка про телефон: при `--host` у телефона свой `localStorage`, поэтому общей встречи с
ноутбуком не будет — это удобно для проверки сетки пальцем. Чтобы показать пример без ввода
данных, нажмите на главной «Посмотреть пример» (6 участников со случайными отметками).

## Как устроен код

```
src/
├─ domain/                # чистая логика без React — потом переедет на сервер
│  ├─ schemas.ts          # Zod-схемы — источник правды, типы выводятся из них
│  ├─ slots.ts            # слоты по 30 минут, часовые пояса, подписи дат по-русски
│  ├─ findBestSlots.ts    # алгоритм поиска лучшего времени (раздел 6 ТЗ)
│  ├─ meetings.ts         # операции над встречей: участники, места, фиксация
│  ├─ merge.ts            # слияние при импорте .meet.json
│  ├─ final.ts            # итог: кто идёт, текст для чата, ссылка на карту
│  ├─ ics.ts              # .ics с напоминаниями за 24 ч и 2 ч, ссылка Google Календаря
│  └─ demo.ts             # демо-данные
├─ storage/
│  ├─ MeetingRepository.ts       # интерфейс — единственная точка работы с данными
│  ├─ LocalStorageRepository.ts  # реализация сейчас
│  └─ migrations.ts              # миграции формата (v1 → v2 …)
├─ hooks/                 # TanStack Query: useMeeting, useSaveAvailability, …
├─ components/            # TimeGrid, Heatmap, Sheet, Toaster, ParticipantPicker, …
├─ pages/                 # Home, NewMeeting, Mark, Results, Places, Final
├─ styles/tokens.css      # все цвета и размеры (светлая и тёмная тема)
└─ main.tsx               # здесь одной строкой подключается хранилище
tests/                    # Vitest для domain/ и storage/
```

**Главное правило:** страницы и компоненты никогда не обращаются к `localStorage` напрямую —
только через `MeetingRepository`. Это проверяет ESLint (`no-restricted-globals` для
`src/pages`, `src/components`, `src/domain`). Все методы репозитория асинхронные, поэтому для
перехода на сервер достаточно написать `ApiRepository` и заменить одну строку в `main.tsx`.

### Решения, которых нет в ТЗ явно

- **Не ответившие участники.** Кто не поставил ни одной отметки, в результатах показан как
  «ещё не отметились» и не блокирует варианты, даже если он «обязательный» — иначе до его
  ответа топ был бы пустым.
- **Поглощённые варианты.** Кроме склейки соседних окон, из топ-3 убираются варианты, которые
  пересекаются по времени с более сильным и подходят тем же людям (например, «Сб 18:00 для
  двоих», когда есть «Сб 20:00 для этих двоих и ещё одного»). Так в топе разные вечера.
- **`settingsUpdatedAt`.** В схему встречи добавлено поле, когда последний раз менялись
  настройки или фиксация. При импорте настройки берутся по нему, а не по `updatedAt`, — иначе
  друг, который просто отметился позже, откатил бы изменения организатора.
- **Перевод часов.** Окно считается «подряд», только если слоты идут через реальные 30 минут;
  несуществующее время (весенний переход) показывается в сетке пустой ячейкой.
- **«Весь вечер»** = 4 часа.
- **Сетка.** Протягивание выделяет прямоугольник от первой ячейки до текущей; если первая
  ячейка уже была в выбранном статусе — прямоугольник стирается. Двумя пальцами сетка
  прокручивается, за время и заголовки дней — тоже.

## Удобные фишки сверх ТЗ

- **Подсказки на сетке** («👥 Другие»): в ячейках цифра — сколько других уже могут в это время.
  Легко «подтянуться» к остальным.
- **Отмена** (кнопка «↶ Отменить» и Ctrl/⌘+Z), история своя у каждого участника.
- **Инструменты отметок** (меню «⋯»): «Повторить Сб на все дни», «Очистить мои отметки» — с
  «Вернуть» в тосте.
- **Клавиши 1 и 2** переключают «Могу» / «Если нужно».
- **Прошедшее время** заштриховано и не отмечается, топ-3 не предлагает уже начавшиеся окна;
  обновляется само раз в минуту.
- **«А если без Макса?»** — на экране результатов можно нажать на имя и посмотреть варианты
  без этого человека (ничего не удаляется).
- **Обратный отсчёт**: «Завтра», «Через 5 дней», «Сегодня, через 3 часа» — на итоге и на
  карточках главной; у собираемых встреч — полоска «отметились 3 из 6».
- **Конфетти** при фиксации (отключается при `prefers-reduced-motion`).
- **«Поделиться с друзьями»** на телефоне: системное меню с текстом и файлом `.ics` сразу —
  можно отправить в любой мессенджер одним действием.
- **«Пусть решит случай» 🎲** в местах: подсветка бегает по списку и останавливается на
  случайном месте; шанс пропорционален лайкам.
- **«Повторить встречу»** в меню «⋯»: та же компания и места, даты сдвигаются на целые недели
  вперёд (пятница остаётся пятницей), отметки и лайки — с чистого листа.
- **Спасение данных**: если повреждена только часть `localStorage`, уцелевшие встречи
  остаются, копия всего сохраняется в `kogda:broken:<дата>`.

### Критерии приёмки (раздел 11)

Проверено автоматически: тесты алгоритма (обязательные случаи + 5 подготовленных наборов),
слияние экспорт → импорт → обратный импорт, битые данные в `localStorage`, отсутствие
`localStorage` в `pages/` и `components/` (ESLint). Проверено вручную в Chromium: сценарий А
целиком, клавиатура на сетке, светлая и тёмная темы, импорт со сводкой, все фишки из списка
выше, удаление и повтор встречи, участники с «Вернуть».

Осталось проверить руками: Safari и телефоны (iPhone, Android) через `--host`, импорт `.ics`
в календарь iPhone и Google Календарь со срабатыванием напоминаний, показ 2–3 друзьям.

## План работ для одного разработчика

ТЗ рассчитано на двоих; здесь оба потока (логика и интерфейс) у одного человека. Этапы 1–5
выполнены в первом подходе, дальше:

1. **Проверка на устройствах (2–3 вечера).** iPhone и Android через `--host`: протягивание без
   прокрутки, вибрация на Android, двухпальцевая прокрутка; Safari на ноутбуке; импорт `.ics`.
2. **Показ друзьям по сценарию А (1–2 вечера).** Записать, где люди застревают, исправить
   топ-5 проблем.
3. **Полировка (по результатам показа).** Пустые состояния, тексты, анимации.
4. **Дальше — полноценная версия** (раздел 12 ТЗ): `ApiRepository`, общая ссылка `/m/:id`,
   `refetchInterval` в TanStack Query.

Коммиты привязываются к ID требований (F1–F16), например `F5: двухпальцевая прокрутка сетки`.
